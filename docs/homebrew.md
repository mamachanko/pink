# Homebrew

Pink is a cask in this existing repository. A nonstandard tap URL avoids creating or purchasing another repository/service:

```sh
brew tap mamachanko/pink https://github.com/mamachanko/pink.git
brew install --cask mamachanko/pink/pink
brew upgrade --cask mamachanko/pink/pink
```

Use the fully qualified cask name to avoid unrelated packages called pink. The universal DMG supports Apple Silicon and Intel on macOS 15+. The initial cask pins v1.0.2 and its actual final SHA-256, independently downloaded and verified. `app "Pink.app"` refers to the application inside the DMG, not its outer filename. The cask does not launch Pink, enable monitoring, register login items, strip quarantine or disable Gatekeeper. Current builds are ad-hoc signed, not Developer ID signed or notarized; per-app approval may be required. Launch Pink and opt in explicitly.

Uninstall with `brew uninstall --cask mamachanko/pink/pink` after disabling login launch and quitting. Add `--zap` only to intentionally remove both current and legacy preferences. Ordinary uninstall preserves settings.

Native CI taps the current checkout locally, audits/styles the real cask, downloads the checksum-pinned DMG, installs into a temporary app directory, verifies the installed bundle, then uninstalls/untaps. It refuses an already configured Pink tap, never installs into the user's Applications directory, and never opens the app or changes system privacy/login permissions. Homebrew's installed version is printed; automatic updates and analytics are disabled during the test.

After semantic-release publishes and verifies a qualifying release, `homebrew-update.mjs` computes the cask checksum from the final signed/stapled DMG and proposes a `homebrew/vVERSION` branch and `chore(homebrew)` PR. It never commits directly to main, merges, replaces release assets or moves tags. No npm/app version or changelog commits are introduced. Only reviewed cask metadata is versioned. Until that PR is merged, Homebrew offers the last reviewed release. Signing-mode caveats follow actual notarization state.

Maintainer setup: permit the publishing job to use contents:write and pull-requests:write and, if desired, enable GitHub's setting allowing Actions to create PRs. Repository files cannot activate that remote setting. GITHUB_TOKEN is sufficient; no broad PAT is needed. GitHub suppresses workflow events generated by GITHUB_TOKEN: a maintainer must reopen a generated PR or otherwise trigger required verification before merging it. Do not bypass required checks. A failed metadata-PR step after publication does not undo the release; resolve permissions and rerun the idempotent metadata step with the already verified version, without replacing assets or tags.

References consulted: Homebrew's official Cask Cookbook, tap-maintenance guide and brew manpage (Homebrew/brew main, 2026-11-13). This is a custom tap, not a claim of inclusion in homebrew/cask.
