# Release process

GitHub Releases are the changelog. `release.config.cjs` uses semantic-release 25.0.9, analyzer 13.0.1, notes 14.1.1, exec 7.1.0, GitHub 12.0.11 and conventionalcommits preset 9.1.0. Node 24.22.1 meets their declared engines. Preset 10.4.1 was tested and rejected because notes generator's writer is incompatible. Lockfile is npm-generated. No npm publication, changelog plugin, git plugin or version commits.

Only main releases; tags `v${version}`. Default conventionalcommits rules give fix/perf patch, feat minor, breaking major including `docs!` and any-type BREAKING CHANGE footers. Nonbreaking docs/test/chore/ci yield no release. No custom no-release rule can suppress breaking changes. Actual analyzer and semantic-release temporary-repo tests verify these decisions and initial 1.0.0.

Reusable verification runs at the exact triggering SHA on arm64 and Intel macOS 15 runners with Xcode 26.2. Required verification checks all native matrix outcomes. Release waits for that workflow, then publishing-only contents:write job uses GITHUB_TOKEN. Full history/tags are fetched. Concurrency serializes release-main and never cancels an active publishing job. Fork PR jobs have read-only permissions and no credentials. No pull_request_target and no tag-triggered second build.

Prepare receives `${nextRelease.version}` directly from semantic-release exec, validates stable numeric version, validates signing configuration, builds universal app and packages it. CFBundleShortVersionString is the release version; CFBundleVersion is a three-component numeric mapping of GITHUB_RUN_NUMBER: `(run / 10000 + 1).(run / 100 % 100).(run % 100)`, with run < 99990000, first component <= 9999 and other components <= 99 (local build 1). Source commit goes into bundle and manifest. Versions are build settings, never tracked file edits. An independently executable `node scripts/prepare.mjs 1.2.3` runs fixed-version package verification on macOS CI.

Outputs are `RefPaste-VERSION-adhoc.zip/.dmg` or `-developer-id`, SHA256SUMS and build-info.json. GitHub plugin asset patterns are explicit; check-assets enforces the exact four filenames. Manifest contains version/build/commit/architectures/minimumOS/toolchain/signing/notarization/CI run identity. Final checksums follow signing/notarization/stapling. Verification extracts ZIP and mounts DMG, checks universal binary/layout/versions/signature/license and launches `--smoke-test` before any general clipboard setup. Postpublish downloads and checks actual assets, compares manifest and tag identity.

Default mode `SIGNING_MODE=adhoc`: **Ad-hoc signed; not Developer ID signed; not notarized.** No Apple account required. No automatic Applications installation. Per-app Open Anyway approval may be available; source building is another option. Never disable Gatekeeper globally.

Developer ID contract: set release environment variable `SIGNING_MODE=developer-id`, variables APPLE_SIGNING_IDENTITY (full Developer ID Application identity) and APPLE_TEAM_ID. Secrets: APPLE_CERTIFICATE_P12_BASE64 (exported cert plus private key), APPLE_CERTIFICATE_PASSWORD, APPLE_ID, APPLE_APP_PASSWORD (app-specific notarization password). All six signing fields are required together. Any partial configuration fails; credentials in adhoc mode also fail. No fallback.

Scripts create a temporary keychain, import certificate, configure codesign partition access, sign hardened app with timestamp, submit ZIP using notarytool --wait, staple/validate app, assess Gatekeeper, then build/sign/notarize/staple/assess DMG. ZIP contains stapled app. No special entitlements. Trap cleans temporary keychain/certificate directory/staging on success/failure. No shell xtrace. Identity import/assessment/notarization failures block publication. Use disposable short-lived credentials and restrict release environment access. Apple docs endpoint access was blocked here; this flow requires current Apple documentation and real credential verification before production release.

Recovery: semantic-release may create a tag before GitHub assets finish publishing. Never delete/move an existing tag or silently replace a known-good release. Inspect workflow logs, tag commit, manifest and checksums. Download surviving assets and compare them before deciding whether a partial release can be completed under explicit maintainer authorization. A rerun alone may report no new release because tag already exists. Prefer a new fix commit/version if integrity cannot be established; document the incomplete release. Never create production releases for tests.

Current execution limitations: no macOS package, certificate cleanup, notarization, Gatekeeper, publication or recovery run was performed on the Linux implementation host. Dry-run engine tests prove version decisions only. Native CI and final signed release remain gates.
