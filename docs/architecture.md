# Architecture and decisions

## User-initiated updates (2026-11-15)

The later user request supersedes the original updater/runtime-dependency prohibition. Sparkle 2.10.1 is the sole runtime exception. Foundation-only `PinkCore` owns stable version/release validation and cancellable, deduplicated check state. `PinkPlatform` owns bounded ephemeral GitHub HTTP reads for manual builds; `App/Updates.swift` owns native UI and lazy Sparkle startup. No updater receives clipboard ports, parsers, host rules or snapshots. No update check runs at launch, wake, permission recovery, smoke test or README capture.

Secure builds require an embedded public Ed25519 key, signed feed/archive and explicit installation confirmation. Unconfigured builds offer manual downloads, never unsigned installation. Keys go to upstream tools through stdin and never enter manifests; temporary staging is cleaned on success/failure. Generation follows final app signing/stapling and precedes final checksums. See [updates.md](updates.md) for signing modes, ad-hoc library-validation exception, key setup and verification limits.

`PinkCore` is Foundation-only: deterministic recognition, escaped HTML, validated versioned settings and a synchronous main-actor state machine. Ports inject pasteboard, representation builder, scheduler and permission policy. `PinkPlatform` implements AppKit serialization, native RTF, timer and privacy preflight. `App` owns status menu, native SwiftUI settings, consent and ServiceManagement. No unchecked Sendable; the timer executes on main RunLoop and uses MainActor.assumeIsolated for that runtime guarantee. No async work inside pasteboard mutation.

Matching uses exact case-insensitive host and explicit port, case-sensitive installation prefix with slash boundary. An omitted rule port means URL must omit its explicit port; add a separate explicit-port rule if needed. Prefix overlaps for enabled rules on the same endpoint are rejected. Display segments support letters/numbers/combining marks, underscore, hyphen, dot and tilde. Valid UTF-8 and unreserved percent escapes are decoded for matching/display only. Encoded separators and reserved path bytes are rejected. Native link attributes receive the original string without URL reserialization. Object numbers remain strings, including leading zeroes when not all zero. Original input is never reserialized. Strictness favors leaving the clipboard alone.

Eligibility allowlist: `public.utf8-plain-text`, `public.url`, `public.html`, `public.rtf`. At least one text/URL representation is necessary; every advertised text/URL representation must decode successfully and agree. URL metadata must itself be one strict, valid URL, never prose. Existing HTML is skipped by default. The opt-in formatted-URL validator described below avoids native HTML import entirely. Existing RTF must decode to exactly the source text, contain no attachments, and have only raw-URL link labels equal to their targets. Named/conflicting links make the whole item ineligible. Validated RTF styles and unchanged spans are preserved. No arbitrary lazy custom payload is read. One item only, each payload <=64 KiB and aggregate <=64 KiB for restoration. Generated output includes the four representations plus `io.github.mamachanko.pink.self.v1` (random in-memory ownership nonce) and `org.nspasteboard.AutoGeneratedType`.

Marker conventions researched from https://github.com/nspasteboard/nspasteboard.github.io/blob/master/index.md on 2026-11-13: ConcealedType, TransientType, AutoGeneratedType; 1Password `com.agilebits.onepassword`; Handoff `com.apple.is-remote-clipboard`; legacy `de.petermaurer.TransientPasteboardType`, `com.typeit4me.clipping`, `Pasteboard generator type`. All are rejected by absence from the allowlist. Sensitive content without markers cannot be identified. No claim of universal sensitivity detection.

Startup/enable/wake/session resume/retry baseline without reading. Unchanged generations aren't read. Own generation is remembered; markers make re-observed self output ineligible. A subsequent external identical copy has a fresh generation and remains eligible. Read failure stops scheduling with Error; permission preflight uses Permission needed. A failed write is never rolled back. Retry is explicit. Pause discards snapshot. External generation prevents restore, then next tick discards it. Snapshot never reaches disk.

There is no atomic inter-process compare-and-swap: another process can copy after the last check and before clear/write, or during write. Both checkpoints reduce this unavoidable window; the synchronous window is kept short. Failure can leave an empty clipboard. Never unconditionally roll back. Clipboard processing also loses a race against immediate paste; original URL remains safe before transformation.

Privacy preflight uses NSPasteboard.accessBehavior with macOS 15.4 guard. Ask/alwaysDeny stop monitoring without prompting; user can adjust the per-app Paste from Other Apps setting where available, then retry. Earlier macOS has no equivalent preflight; failed reads stop the watcher. Default behavior is permitted to follow OS policy. SDK declarations were cross-checked with maintained dotnet/macios AppKit bindings; Apple's official documentation endpoint was proxy-blocked. Native availability and behavior still require macOS verification.

Versioned settings use UserDefaults `settings.v1`; malformed data defaults to no consent and no automatic monitoring. Launch at login isn't inferred from defaults: UI reads actual SMAppService status. App is unsandboxed, hardened, without special entitlements. Icon is generated locally with AppKit; no image download.

XcodeGen source is pinned by commit and its genuine upstream Package.resolved is committed in tools. Application package has zero remote Swift dependencies, so SwiftPM does not create a root Package.resolved. Node dependencies have npm's genuine integrity lock. Xcode 26.2 selected from both current official runner inventories, macOS 15 deployment and universal ARCHS retained. Native execution matrix is macos-15 (arm64) and macos-15-intel (x86_64); cross-builds aren't native coverage.

Post-write ownership is checked again using the nonce and a stable observed generation before recording self-write state. An external copy immediately after serialization remains unconsumed and is processed on the next tick. This closes a watcher bookkeeping race, without claiming inter-process atomic mutation.

On willSleep and session resignation, App pauses the scheduler and invalidates restoration. Wake/reactivation enables only previously active automatic monitoring and establishes a new baseline. Permission/error states are not automatically retried by wake. Native ownership checks read only the bounded private nonce, avoiding rich-data materialization while attributing a write.

## Pink identity and upgrade

The product is Pink (💕). Swift modules/targets are PinkCore and PinkPlatform; the application, executable, icon, project and packages use Pink. Bundle and logging identity is `io.github.mamachanko.pink`, with private clipboard marker `io.github.mamachanko.pink.self.v1`. Build inputs use PINK_VERSION, PINK_BUILD, PINK_COMMIT, PINK_NOTARIZATION and PINK_TEMP_ROOT. Repository identity remains mamachanko/pink.

SettingsStore validates and re-encodes the known version-1 settings from the former `io.refpaste.app` preferences domain only when Pink has no saved settings. Existing Pink settings take priority; invalid current or legacy settings fail safely without reviving old consent. Clipboard contents, snapshots and unrelated preferences are never copied. Legacy identifiers remain only for this preference import and cleanup of generated packages from the previous name. The new bundle identity has separate macOS clipboard and login approval: never migrate or register those automatically. Quit/remove the previous app and its login item, then opt in for Pink if desired. Older verification records retain their original artifact filenames.

Distribution names are verified at four levels: exact sole root `Pink.app`, sole `Pink` executable, bundle/localized display metadata, and mounted volume name `Pink`. The owned app product is recreated before building so incremental output cannot retain retired resources. Published v1.0.1/v1.0.2 DMGs are independently audited read-only in native CI; historical v1.0.0 is not renamed/replaced. Homebrew uses the existing repository as a custom tap with checksum-pinned metadata; release automation proposes reviewed cask updates on a separate branch and never writes versions directly to main. See homebrew.md.

Workflow action implementations now explicitly run on Node 24: checkout v7.0.1, setup-node v7.1.0, cache v6.1.0 and upload-artifact v7.0.2. Full commit pins and upstream action.yml runtime declarations were checked. This fixes the action runtime rather than suppressing Node 20 warnings or changing only the selected application-development Node version.

## URLs embedded in prose

The 2026-11-13 feature request replaces the original whole-URL-only product scope. `Parser.parse` remains a strict, pure single-URL validator; `Parser.parseText` produces a bounded `FormattedText` containing exact source spans and validated `Reference` replacements. One immutable original string remains the plain-text representation. Invalid/unknown URLs are left as text, not repaired, and links nested in another URL token are never extracted. Multiple URLs are still one pasteboard item, not multiple items.

Token matching is Foundation-only and local. Candidates begin at a prose boundary (start, whitespace, opening delimiter/quote); a complete scheme token is consumed before validation. Ordinary adjacent words/path fragments are not link boundaries. Whitespace and quotes delimit prose, unmatched closing brackets/parentheses stay outside links, and sentence punctuation is removed only if the entire candidate fails strict validation. Valid query/fragment punctuation remains part of the original target. Ambiguous adjacent URLs without separators remain untouched. At most 32 boundary reductions per candidate and an 8 KiB document cap bound work on the main actor; the regex avoids rescanning long scheme-like words quadratically. HTML source and named Markdown destinations are excluded; this is not a Markdown/HTML parser.

Generated HTML escapes prose as well as labels/targets and uses explicit line breaks plus preserved whitespace. Native RTF replaces source ranges backwards in UTF-16 coordinates, retaining validated original styles outside replacements and inheriting the URL's first-character style for each new label. This avoids emoji/combining-character offset errors and shifted ranges after earlier replacements. If an existing raw RTF autolink overlaps a proposed replacement, its range and target must agree exactly; a narrower existing target makes the item ineligible rather than changing its destination. URL metadata is emitted only for an entire single-URL item. The same generation/ownership checks, bounded restoration snapshot and synchronous write window apply to the entire document. No new payload types, permissions, network access or persistent clipboard data are introduced.

Artifact verification shares a read-only mount helper for newly built and audited published DMGs. Four attempts are permitted only for the observed DiskImages “Resource temporarily unavailable” attach error, with 1/2/4-second backoff. Every failure is logged; all other errors and exhausted retries fail immediately. Commands and delays are injectable for deterministic tooling tests. A successful mount still undergoes every layout, identity, signature, checksum and smoke check; no failed verification can publish.

## Required checks and serialized cask maintenance (2026-11-14)

`Required checks` is the unique PR merge gate; title/source-commit validation and full reusable verification are prerequisites. The verification aggregate includes native UI capture, both native architectures and all package checks. Unexpected skipped/cancelled/missing jobs fail. Only the title job may skip for a main push. PR title edits rerun CI, and same-branch obsolete CI runs can be cancelled; an active release publication is never cancelled. `workflow_dispatch` attests the exact open same-repository PR head with a read-only token.

Cask maintenance is a separate trusted-main workflow using only published, checksum-verified assets and tag/manifest identity. A single `homebrew/update` branch is refreshed with a commit rooted in main's tree and parents retaining the previous branch tip. This resolves generated metadata drift without force pushing or discarding unrelated source changes. The generated cask digest trailer rejects manual branch edits, and PR notes outside the generated block survive. Current-main templates take priority over an older checkout. Strict base checks cover the remaining main-change race; main pushes and Release completion trigger refresh. See homebrew.md for version monotonicity, obsolete-PR guards and failure recovery.

This intentionally replaces the original publishing-only write model: publication retains contents write; a separate main-only maintenance job has narrowly scoped contents, PR and actions write permissions to update metadata and dispatch secret-free CI. It neither merges PRs nor grants write permissions to untrusted PR code. No additional long-lived credentials are required. The prepared main ruleset has no bypass actors and requires PRs, the observed GitHub Actions gate, strict base freshness, resolved threads and squash/rebase linear history. Zero required approvals avoids a single-owner self-approval deadlock; this does not enable automatic merging. Live activation is a separate administrator action and must be read back, never inferred from the policy file.

## Configurable link formats (2026-11-16)

The link-builder request extends service recognition with deterministic, compiled URL patterns. `LinkURL` performs the shared strict URL validation; it reads the original path rather than Foundation's repaired/encoded representation so mixed literal Unicode and percent escapes keep their boundaries. Unreserved escapes, UTF-8 and encoded filename spaces are decoded for matching only. Reserved encoded separators remain unsupported. Service namespace/number checks still apply to built-in issue/review routes.

`LinkRule` stores an identity, name, URL pattern, plain-text label template, enabled state and explicit preset-override flag. Whole-segment named captures match one segment; a final remainder capture matches one or more segments. No regular expressions or scripts come from settings. Patterns require exact validated scheme/host/port, literal path components, unique capture names and known label substitutions; queries/fragments cannot be pattern syntax. There are at most 64 rules, 64 segments per pattern, 2 KiB pattern bytes, 512 template characters and 8 KiB output label bytes. Invalid disabled rules are also rejected at save/load. Rule identities must be unique.

`Parser.matches` produces ordered references and capture values for both parsing and preview: explicit overrides in list order, the enabled host's service preset, then other custom rules in list order. The first candidate wins, without feeding its label or target into another rule. Overlaps are visible in preview and resolved by explicit ordering. Existing enabled service host-prefix overlap validation remains unchanged. A custom HTTP pattern is an explicit endpoint opt-in; public github.com/gitlab.com HTTP remains forbidden. Invalid rules report fixed errors without echoing settings/clipboard data into logs.

GitHub presets add repository roots, blob files and tagged releases. Known top-level site routes are excluded from repository-owner matching. Blob labels keep revision/path together rather than infer slash-containing branch names offline; recognized positive, ordered `L10`/`L10-L20` fragments append line indicators. Full 40/64-character hexadecimal revisions are shortened to eight characters in the label only. GitLab blob files use the same revision/path treatment, with `L10`, `L10-20` and `L10-L20` anchors, nested namespaces, and configured installation prefixes/ports. Other fragments and all queries remain in the original target. GitLab issue/merge-request routes retain their existing nested-namespace behavior. Unknown/malformed/reversed line anchors add no line suffix; all original targets remain exact. The enabled GitHub.com preset supplies every supported GitHub kind without custom rules; settings list these bundle capabilities and label templates as customization. In prose, terminal sentence punctuation is removed from query/fragment-free URL tokens before matching so generic captures do not swallow it. Whole-URL items and explicit query/fragment targets retain existing exact-target behavior. Dot path segments cannot be shortened away as punctuation.

Version-1 settings gain an optional `linkRules` field. Its absence loads an empty custom list while preserving consent, monitoring state and enterprise hosts; a present malformed field fails validation. Examples and the builder draft are view state, and only committed rule configuration reaches SettingsStore. The two settings tabs keep service-host configuration available alongside editable custom starter presets. `PINK_README_CAPTURE` captures the real link builder with a reserved-host Jira example as `link-formats.png`, without touching preferences or the general pasteboard.

## Copied HTML autolinks (2026-11-16)

`Settings.rewriteFormattedURLs` is opt-in and absent version-1 preferences decode it as false without changing consent, host rules or custom formats. Save replaces the main-actor representation builder and re-establishes the existing baseline; changing this setting alone never rewrites the clipboard.

`PinkCore.HTMLClipboard` is a bounded conservative fragment validator, not an HTML renderer. It accepts UTF-8, common presentational/block wrappers, quoted attributes, browser fragment comments, charset metadata, br/wbr and a small documented-in-source entity set. It rejects unknown tags, resources, images, scripts/style blocks, event attributes, malformed/ambiguous attributes, unknown entities, DTDs and processing instructions. It normalizes tag case and void elements for Foundation XMLParser, disables external entities with both APIs and returns nil on every parser/validation error. The official Swift FoundationXML source confirms the entity policy; Apple's documentation endpoint returned 403 in this environment.

HTML layout whitespace is normalized only for comparison and UTF-16 position mapping. Every non-whitespace unit must agree with original plain text. Each HTML anchor must have an absolute credential-free HTTP(S) target equal to its entire decoded visible label, and its mapped original substring must equal that target exactly. Replacement ranges must also agree with every overlapping HTML/RTF anchor. Thus a known target cannot silently gain sentence punctuation. Unsupported/ambiguous cases skip the entire item; named links remain protected even with the option enabled. Existing pure URL/custom-format recognition remains authoritative about which targets are shortened.

Limits: 64 KiB source HTML (plus the existing 64 KiB aggregate snapshot), 8 KiB original text, 32 KiB decoded fragment text, 64 nesting levels and 128 anchors. No AppKit HTML import, DOM, browser, resource loading or new runtime dependency is introduced. Presentational CSS is never interpreted/copied. Generated HTML uses the existing escaped representation; RTF preserves validated source styles when RTF is available, otherwise it is generated from plain text. Plain bytes are never normalized. Restoration retains the exact original payload in memory, subject to the same ownership/race checks. The clipboard type allowlist and all sensitive/custom/remote markers are unchanged.

## Paste-first link builder (2026-11-17)

`LinkSuggestion` is Foundation-only, ephemeral derivation from one strictly validated URL. It selects a Jira issue key or the final generic path segment, recognizes supported public GitHub routes, and generates a normal `LinkRule`. GitHub owners/repositories generalize together; file revision/path and slash-containing release tags stay opaque. Context is a label choice. No network lookup, arbitrary regex or automatic clipboard read is used. A generated pattern must compile and match its own source before being offered.

Literal pattern segments now accept the same safe percent escapes as copied URLs, so static directory names with encoded spaces or Unicode remain representable. Validation reads original pattern bytes, substitutes safe placeholders only for validation, and uses the shared `LinkURL` validator before constructing compiled literal/capture segments. Encoded separators, invalid UTF-8, dot segments, escaped controls and encoded capture braces stay rejected. The target is never reconstructed from the pattern.

The native primary Add format action opens a paste-first builder with selectable path parts, optional context and a prominent preview. Advanced syntax is collapsed. Already-supported links preview existing behavior with a no-write Done action. Explicit customization prefers the proposed pattern; it is inserted before overlapping patterns, while exact-pattern edits retain rule identity. Preview evaluates the complete proposed settings with the clipboard parser rather than rendering a separate approximation. Saving uses the existing transactional settings session once; failures keep the draft. The local Undo notice restores the prior rule collection, including order, only while it still exactly equals the applied collection; another format edit clears the notice. It does not restore unrelated settings or clipboard state.

Portable tests cover future Jira tickets, context/selection, installation prefixes and ports, GitHub generalization, Unicode/encoded literals, roots, malformed input and a one-save settings/monitor/restoration flow. A native test persists the suggested format into isolated preferences and then formats/restores a different ticket on a unique named pasteboard, checking native RTF text and the exact target. The documentation capture target renders the actual builder from an example URL without supplying a pattern. The capture script builds for its native host architecture; its CI job uses Intel while the independent native matrix still requires Apple Silicon and Intel. Manual receiver, keyboard, VoiceOver and release-install acceptance must still be recorded separately.


## Conventional link presentation and Actions

Application formatting uses `Parser(settings:)` to combine route recognition, custom-rule precedence and `Settings.showLinkIcons`. This optional version-1 field defaults to true, including migrated settings, and preserves an explicit false. Low-level `Parser(rules:linkRules:showLinkIcons:)` retains its plain-label default for existing callers. All application clipboard and preview paths use the saved preference. Changing it replaces the parser only, leaving monitor ownership/baseline and Restore intact. Patterns never store the presentation prefix.

Built-ins classify repositories, issues, reviews, files, releases, commits and GitHub Actions workflows/runs/jobs. Jira ticket icons require an active custom format and the same conventional browse/key recognition as the builder. Classification never enables an unmatched host or fetches server status. Prefixes also apply to custom overrides of an enabled preset; authored leading emoji are retained. Unknown custom links retain their labels.

GitHub/GitHub Enterprise Actions routes validate the entire route and positive ASCII run/job/attempt IDs; workflows accept a single YAML basename or numeric workflow ID. Commit routes use 7–64 hexadecimal characters; labels show at most eight. Full revision tokens in conventional custom file/commit labels are also shortened, leaving raw captures and patterns unchanged. Full 40/64-character file revisions now also show eight characters, while branch/tag paths stay opaque and destinations remain exact. GitLab commit links share the commit treatment. Icons are part of the rich link label, so native named-pasteboard tests verify Unicode/variation-selector UTF-16 link ranges, original targets, plain text, preference changes and restoration.
