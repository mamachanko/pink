# Architecture and decisions

`PinkCore` is Foundation-only: deterministic recognition, escaped HTML, validated versioned settings and a synchronous main-actor state machine. Ports inject pasteboard, representation builder, scheduler and permission policy. `PinkPlatform` implements AppKit serialization, native RTF, timer and privacy preflight. `App` owns status menu, native SwiftUI settings, consent and ServiceManagement. No unchecked Sendable; the timer executes on main RunLoop and uses MainActor.assumeIsolated for that runtime guarantee. No async work inside pasteboard mutation.

Matching uses exact case-insensitive host and explicit port, case-sensitive installation prefix with slash boundary. An omitted rule port means URL must omit its explicit port; add a separate explicit-port rule if needed. Prefix overlaps for enabled rules on the same endpoint are rejected. Display segments support letters/numbers/combining marks, underscore, hyphen, dot and tilde. Valid UTF-8 and unreserved percent escapes are decoded for matching/display only. Encoded separators and reserved path bytes are rejected. Native link attributes receive the original string without URL reserialization. Object numbers remain strings, including leading zeroes when not all zero. Original input is never reserialized. Strictness favors leaving the clipboard alone.

Eligibility allowlist: `public.utf8-plain-text`, `public.url`, `public.html`, `public.rtf`. At least one text/URL representation is necessary; every advertised text/URL representation must decode successfully and agree. URL metadata must itself be one strict, valid URL, never prose. Existing HTML is conservatively skipped, because native HTML import may fetch resources. Existing RTF must decode to exactly the source text, contain no attachments, and have only raw-URL link labels equal to their targets. Named/conflicting links make the whole item ineligible. Validated RTF styles and unchanged spans are preserved. No arbitrary lazy custom payload is read. One item only, each payload <=64 KiB and aggregate <=64 KiB for restoration. Generated output includes the four representations plus `io.github.mamachanko.pink.self.v1` (random in-memory ownership nonce) and `org.nspasteboard.AutoGeneratedType`.

Marker conventions researched from https://github.com/nspasteboard/nspasteboard.github.io/blob/master/index.md on 2026-11-13: ConcealedType, TransientType, AutoGeneratedType; 1Password `com.agilebits.onepassword`; Handoff `com.apple.is-remote-clipboard`; legacy `de.petermaurer.TransientPasteboardType`, `com.typeit4me.clipping`, `Pasteboard generator type`. All are rejected by absence from the allowlist. Sensitive content without markers cannot be identified. No claim of universal sensitivity detection.

Startup/enable/wake/session resume/retry baseline without reading. Unchanged generations aren't read. Own generation is remembered; markers make re-observed self output ineligible. A subsequent external identical copy has a fresh generation and remains eligible. Read failure stops scheduling with Error; permission preflight uses Permission needed. A failed write is never rolled back. Retry is explicit. Pause discards snapshot. External generation prevents restore, then next tick discards it. Snapshot never reaches disk.

There is no atomic inter-process compare-and-swap: another process can copy after the last check and before clear/write, or during write. Both checkpoints reduce this unavoidable window; the synchronous window is kept short. Failure can leave an empty clipboard. Never unconditionally roll back. Clipboard processing also loses a race against immediate paste; original URL remains safe before transformation.

Privacy preflight uses NSPasteboard.accessBehavior with macOS 15.4 guard. Ask/alwaysDeny stop monitoring without prompting; user can adjust the per-app Paste from Other Apps setting where available, then retry. Earlier macOS has no equivalent preflight; failed reads stop the watcher. Default behavior is permitted to follow OS policy. SDK declarations were cross-checked with maintained dotnet/macios AppKit bindings; Apple's official documentation endpoint was proxy-blocked. Native availability and behavior still require macOS verification.

Versioned settings use UserDefaults `settings.v1`; malformed data defaults to no consent and no automatic monitoring. Launch at login isn't inferred from defaults: UI reads actual SMAppService status. App is unsandboxed, hardened, without special entitlements. Icon is generated locally with AppKit; no image download.

XcodeGen source is pinned by commit and its genuine upstream Package.resolved is committed in tools. Application package has zero remote Swift dependencies, so SwiftPM does not create a root Package.resolved. Node dependencies have npm's genuine integrity lock. Xcode 26.2 selected from both current official runner inventories, macOS 15 deployment and universal ARCHS retained. Native execution matrix is macos-15 (arm64) and macos-15-intel (x86_64); cross-builds aren't native coverage.

Post-write ownership is checked again using the nonce and a stable observed generation before recording self-write state. An external copy immediately after serialization remains unconsumed and is processed on the next tick. This closes a watcher bookkeeping race, without claiming inter-process atomic mutation.

On willSleep and session resignation, App pauses the scheduler and invalidates restoration. Wake/reactivation enables only previously active automatic monitoring and establishes a new baseline. Permission/error states are not automatically retried by wake. Native ownership checks read only the bounded private nonce, avoiding rich-data materialization while attributing a write.

## Pink identity and upgrade

The product is Pink (💕). Swift modules/targets are PinkCore and PinkPlatform; the application, executable, icon, project and packages use Pink. Bundle and logging identity is `io.github.mamachanko.pink`, with private clipboard marker `io.github.mamachanko.pink.self.v1`. Build inputs use PINK_VERSION, PINK_BUILD, PINK_COMMIT, PINK_NOTARIZATION and PINK_TEMP_ROOT. Repository identity remains mamachanko/pink.

SettingsStore validates and re-encodes the known version-1 settings from the former `io.refpaste.app` preferences domain only when Pink has no saved settings. Existing Pink settings take priority; invalid current or legacy settings fail safely without reviving old consent. Clipboard contents, snapshots and unrelated preferences are never copied. Legacy identifiers remain only for this preference import and cleanup of generated packages from the previous name. The new bundle identity has separate macOS clipboard and login approval: never migrate or register those automatically. Quit/remove the previous app and its login item, then opt in for Pink if desired. Older verification records retain their original artifact filenames.

Distribution names are verified at four levels: exact sole root `Pink.app`, sole `Pink` executable, bundle/localized display metadata, and mounted volume name `Pink`. The owned app product is recreated before building so incremental output cannot retain retired resources. Published v1.0.1/v1.0.2 DMGs are independently audited read-only in native CI; historical v1.0.0 is not renamed/replaced. Homebrew uses the existing repository as a custom tap with checksum-pinned metadata; release automation proposes reviewed cask updates on a separate branch and never writes versions directly to main. See homebrew.md.

Workflow action implementations now explicitly run on Node 24: checkout v7.0.1, setup-node v7.1.0, cache v6.1.0 and upload-artifact v7.0.2. Full commit pins and upstream action.yml runtime declarations were checked. This fixes the action runtime rather than suppressing Node 20 warnings or changing only the selected application-development Node version.

## URLs embedded in prose

The 2026-11-13 feature request replaces the original whole-URL-only product scope. `Parser.parse` remains a strict, pure single-URL validator; `Parser.parseText` produces a bounded `FormattedText` containing exact source spans and validated `Reference` replacements. One immutable original string remains the plain-text representation. Invalid/unknown URLs are left as text, not repaired, and links nested in another URL token are never extracted. Multiple URLs are still one pasteboard item, not multiple items.

Token matching is Foundation-only and local. Candidates begin at a prose boundary (start, whitespace, opening delimiter/quote); a complete scheme token is consumed before validation. Ordinary adjacent words/path fragments are not link boundaries. Whitespace and quotes delimit prose, unmatched closing brackets/parentheses stay outside links, and sentence punctuation is removed only if the entire candidate fails strict validation. Valid query/fragment punctuation remains part of the original target. Ambiguous adjacent URLs without separators remain untouched. At most 32 boundary reductions per candidate and an 8 KiB document cap bound work on the main actor; the regex avoids rescanning long scheme-like words quadratically. HTML source and named Markdown destinations are excluded; this is not a Markdown/HTML parser.

Generated HTML escapes prose as well as labels/targets and uses explicit line breaks plus preserved whitespace. Native RTF replaces source ranges backwards in UTF-16 coordinates, retaining validated original styles outside replacements and inheriting the URL's first-character style for each new label. This avoids emoji/combining-character offset errors and shifted ranges after earlier replacements. URL metadata is emitted only for an entire single-URL item. The same generation/ownership checks, bounded restoration snapshot and synchronous write window apply to the entire document. No new payload types, permissions, network access or persistent clipboard data are introduced.
