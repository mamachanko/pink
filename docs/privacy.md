# Privacy

Pink formats clipboard content locally without network requests. Explicit **Check for Updates** actions contact GitHub for release metadata or a signed Sparkle appcast; confirmed update downloads also use GitHub's release-asset delivery hosts. GitHub receives normal connection information, including IP address and request headers. The manual checker uses an ephemeral URLSession without cookies, credentials or disk cache. No clipboard bytes, copied URLs, labels, private hosts, credentials or snapshots are sent, logged or persisted. Explicit About/update buttons can open release pages in the browser. Clipboard diagnostics contain fixed categories and state transitions only; Sparkle may log update errors about the public feed. Settings necessarily store configured hostnames, custom URL patterns and label templates locally in UserDefaults. Only rules explicitly added/updated and saved enter preferences; preview examples remain in memory and are never logged or persisted. No analytics/crash-upload service; Sparkle system profiling and release-note loading are disabled.

There are no launch-time/background update checks, silent downloads or unattended installation. Sparkle is created on the first user-initiated check only. Its native dialog downloads an update after confirmation, validates the signed feed and archive before extraction, replaces the app and offers relaunch. Sparkle may retain public feed/update caches and update preferences; these contain no clipboard data. Quit cancels manual release checking. See [updates](updates.md) for the release trust model and signing configuration.

Reads are limited to one eligible item with known types after consent. Unknown types and community sensitive/transient/generated/remote markers prevent data reads. Missing markers do not establish that data is safe. Existing HTML is skipped without importing it, preventing resource fetching. No destination app inspection or keyboard hook.

Prose formatting processes at most 8 KiB of text per item. Unsupported URLs remain unchanged. A single item may contain multiple supported links, but all original prose remains the plain representation. Matching and RTF generation stay local; existing named links, HTML and attachment-bearing RTF remain ineligible.

One original snapshot (<=64 KiB) exists in memory only while restoration may be safe. External change, pause and exit invalidate ownership. A restore cannot retract text already pasted. Memory isn't cryptographically erased. OS clipboard and other clipboard tools remain outside Pink's control.

No Accessibility, Input Monitoring or Screen Recording permissions are needed. Clipboard policy is preflighted on macOS 15.4+; Ask/Deny requires user settings action. Do not repeatedly retry reads after failure. Earlier systems may not expose denial as a distinct category; failed reads show Error. Platform behavior remains NOT RUN until tested on macOS.
